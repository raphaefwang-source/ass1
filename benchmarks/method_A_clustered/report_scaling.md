# Fixed-accuracy scaling: pair-summed direct periodic sum vs optimised matrix-free PPPM (Method A), N = 128 … 4096

Starting point: commit `4f2b326` (branch `claude/issue-2-psearch-direct512`); work branch `claude/method-a-scaling`.
Every number is read from a file in `results_scaling/`. Tables are generated by `report_tables_scaling.py`; the full
set is in `results_scaling/report_tables.md`. Earlier results, configurations and reports are untouched.

## 0. Results

Strong N = 128 … 4096 (the priority set) and uniform at the same N. All timings were measured on one machine (Intel Xeon
@ 2.10 GHz VM, 4 cores, L2 2 MiB per core, L3 260 MiB shared) in one process with every BLAS pool at 1 thread (threadpoolctl), using
interleaved repetitions. Medians are reported.

### Crossover

- **Single action:** the pair-summed Direct action is faster than optimised PPPM at N = 128, 256 and 512.
  - Direct/PPPM = 0.15 / 0.35 / 0.78 (strong) and 0.14 / 0.35 / 0.74 (uniform).
  - It is slower from N = 1024 on: 1.36, 3.12, 7.83 (strong) and 1.32, 3.15, 9.60 (uniform) at N = 1024, 2048, 4096.
  - The measured crossover therefore lies between N = 512 and N = 1024. Log-linear interpolation of the two bracketing
    ratios gives N ≈ 700 (strong) and ≈ 740 (uniform); this is an interpolation, not a measurement.
- **End to end with changing positions,** T_total(q) = T_setup + q T_action:
  - PPPM is cheaper at every measured N for q = 1, 10, 40, 80.
  - Direct setup is 29–91 × PPPM setup.
  - Direct/PPPM at q = 80 is 1.9–2.0 (N = 128) … 10.3–12.4 (N = 4096).
  - Direct becomes cheaper only beyond q ≈ 172–176 actions per configuration at N = 128, 217–224 at N = 256 and 608–627
    at N = 512. From N = 1024 there is no break-even: Direct is slower in both setup and action.

### Is the comparison accuracy-matched?

- Both methods meet the same target with the same certification standard: an a-priori spectral-norm bound
  ≤ τ Λ_lb, Λ_lb ≤ ‖Γ_ref‖₂.
- Both were verified against the same independent Γ_ref.
- PPPM's measured error (2.6–5.0e-8) is 1.8–3.6 × smaller than Direct's (8.2e-8 … 1.0e-7). Both certificates are spent
  almost completely, but PPPM's mesh bound overestimates its error more.

## 1. Problem, methods and what is fixed

**Operator.** Manuscript Eqs. (kernelA), (Kper), (Gamma), the request's Eqs. (7)–(9):

  (ΓX)_i = Σ_{j≠i} K^per(q_i − q_j)(X_i − X_j),   K^per(r) = Σ_n K(r + nL),   K(r) = c e^{−κr}/r · r̂r̂ᵀ.

- Constants from `common.py`, unchanged: γ = 0.5, κ = 0.7, r_ref = 1.3, c = 1.6148.
- ρ = 0.75 and L = (N/ρ)^{1/3}.
- Full periodic lattice sum, k = 0 retained, no minimum image.
- Target relative spectral-norm error τ = 2e-7 for both methods at every N.

**Configurations** (fixed density, reproducible):
- Families: `strong` (2 Gaussian clouds, requested width 0.08 L, the priority set) and `uniform`, for N = 128, 256, 512,
  1024, 2048, 4096.
- N = 256 and 512 are the existing `configs/*_N{256,512}_s1.npz`, unchanged (the earlier N = 512 dataset is the
  reference point).
- The other N were made by the same generator with the same seeds (`clustered_configurations.generate(fam, N, 1)`;
  `configs_scaling/`).
- Every configuration has periodic d_min ≥ 0.9.
- The strong clouds relax to 2.14–2.19 × the requested width at every N. The clustering is therefore self-similar in
  units of L (`results_scaling/configurations.json`).

**Direct (primary comparator)**, `direct_periodic.DirectPairs`, unchanged in substance:
- **Setup.** For each configuration, tabulate K^per_{R_d}(q_i − q_j) = Σ_{|q_i − q_j + nL| ≤ R_d} K(q_i − q_j + nL) for
  all N(N − 1)/2 pairs. The image sum is streamed over lattice-shift blocks; images are not stored.
- **Action.** (ΓX)_i = Σ_j K^per_ij (X_i − X_j), a vectorised loop over the pairs (`gather`, 3 × 3 product, `bincount`).
  This is O(N²) pair work per action.
- **One-time preprocessing** (depends on N, L, R_d only; `DirectGeometry`): the pair index arrays and the
  lattice-shift list. They are excluded from the setup timing and reported separately.
- **Changes made here:**
  - the one-time/setup separation (`geom=` argument);
  - a streaming certified tail bound (`degree_bound_curve`);
  - a tighter, still rigorous, tail beyond R_max (summation by parts with each particle's exact image count).

  The kernel evaluation and the action are unchanged.
- **Not used as timing competitors:** the dense GEMV and the image-resolved action. The latter is used only as a
  correctness check at N ≤ 256.

**PPPM**, Method A as in the earlier rounds:
- Ewald split at s = ξ²; existing B-spline PPPM.
- (ξ, r_c, k_c, M, p) chosen separately for every N and configuration by the joint certified budget with the
  Hurwitz-zeta mesh bound (`joint_optimizer`, approach C). The bound was re-validated for p = 12, 13 in
  `results_scaling/alias_bound_validation_p12_13.json`; p = 4…11 were validated in the previous round.
- The production action is the faster, measured, of the two numerically identical implementations (cached D−H /
  pair-difference).
- **Setup:** periodic KD-tree images, short-range weights, B-spline stencil, mesh degree (plus the D_i cache for the
  cached form).
- **One-time per parameter set:** the `Mesh` (influence function on the M³ grid). Excluded from setup, reported
  separately.

## 2. Accuracy-matched parameter selection

**PPPM:**
1. Cost model recalibrated at every N (strong configuration; used for uniform at the same N):
   - per-p spread/gather, S_p + G_p M³;
   - real space, C_R per image;
   - FFT + influence, C_F M³ ln M³;
   - per-p glue;
   - for both implementations (`results_scaling/cost_model_N*.json`).
2. Joint search:
   - p ∈ {6, …, 12};
   - ξ ∈ [0.50, 1.30] on a 0.025 grid (grid r_c, an upper bound), then 0.005 steps within ±0.025 of each p's best;
   - exact r_c by bisection on the certified ε_S for each p's optimum and its alternatives;
   - k_c on exact reciprocal shells; M 2,3,5-smooth with M ≤ M_cap = 128 (N/512)^{1/3}.
3. Justification of the restricted ranges:
   - p = 5 was 4.9–5.7 × slower than the optimum at N = 512 in the previous round, and p = 6 is already far from optimal
     at every N here;
   - the FFT term alone at M_cap is 192 ms (N = 512) … 2075 ms (N = 4096), ≫ every optimum;
   - boundary flags (p, ξ, M) are reported per N.
4. Measurement:
   - screening, interleaved, of every p's model optimum plus the (k_c, M) alternative and ξ ± 0.025 neighbours of the
     3 best predicted p;
   - confirmation, interleaved, of the 4 fastest plus the fastest of every p;
   - measured optimum = the fastest confirmed (candidate, implementation) whose E_op was verified ≤ τ.

**Direct:**
- R_d = the smallest radius on a 0.125 grid whose certified bound satisfies
  2 [max_i λ_max(Σ_{discarded images of i} K) + tail beyond 40] ≤ τ Λ_lb.
- This is the same standard as the PPPM certificate: an absolute spectral-norm bound divided by
  Λ_lb = max_i λ_max(Γ_ref,ii) ≤ ‖Γ_ref‖₂.
- The bound is evaluated exactly for all images up to 40 (streamed). The tail beyond 40 uses summation by parts with
  each particle's exact image count inside 40.

**Accuracy verification**, against the independent reference Γ_ref:
- Γ_ref is `LatticeFriction`, rel_tol 1e-13: near images direct, far images by a Chebyshev fit.
- It is generated for every N up to 4096 (1.2 GB at N = 4096; `raw/`, git-ignored).
- It is cross-checked at every N against the unsplit direct sum to R = 36.

| quantity | N ≤ 1024 | N = 2048 | N = 4096 |
|---|---|---|---|
| ‖Γ_ref‖₂ | dense eigvalsh | dense eigvalsh | ARPACK λ_max of the PSD matrix |
| PPPM E_op = ‖Γ_h − Γ_ref‖₂/‖Γ_ref‖₂ | dense (vectorised `dense_fast`, identical to `GammaH.dense` to 2e-15) | ARPACK | ARPACK |
| Direct E_op | dense | dense + ARPACK | ARPACK |

Notes on the verification methods:
- **Dense norms** are max |eig(sym part)| + ‖antisym part‖_F (both reported). The antisymmetric part is at round-off.
- **ARPACK** (`scipy.sparse.linalg.eigsh`, 'LM', tol 1e-6):
  - applies the matrix-free method and Γ_ref by GEMV; it is not a probe estimate;
  - yields the largest-magnitude eigenvalue of the symmetric error operator, i.e. a Krylov estimate of the spectral
    norm. It converges from below in exact arithmetic and is not a certificate;
  - is cross-checked against the dense value where both exist (§3).
- **Certified vs measured.** Certified means the a-priori bound (both methods). Measured means the spectral norm
  against Γ_ref. The PPPM quadrature term remains an estimate, and floating-point round-off is not certified (§8).

What the optimum looks like:
- **p:** 9 everywhere.
- **Mesh:** constant spacing h = L/M = 0.217–0.222, so M³/N = 122–130, the 2,3,5-smooth sizes nearest to a fixed h.
- **ξ and r_c:** ξ decreases and r_c increases with N. Real-space interactions per particle grow 135 → 346 (strong) and
  143 → 309 (uniform) between N = 128 and 4096.
- **Why.** The certified Fourier and mesh bounds sum ‖K̂_L(k)‖ over the reciprocal lattice. That is N-coherent: at fixed
  (ξ, k_c, h) the bound grows ∝ N at fixed density. The joint optimiser keeps the total at τ by lowering ξ and η, which
  damps K̂_L at high k, and pays for it in real space.
- **Budget shares:** the mesh bound takes 56–74 %, real space 26–44 %, Fourier < 0.4 %.
- **Measured error** stays at 2.6–5.0e-8 at every N, so the margin of the mesh/Fourier certificate grows with N. This is
  a property of the certificate, not of the PPPM error (§8).
- **Production action:**
  - The confirmation run (≥ 40 interleaved rounds) fixed the production implementation before the final timing: the
    pair-difference action everywhere except strong N = 4096, where cached D−H was 2.7 % faster there (289 vs 297 ms).
  - In the final run the pair-difference action was the faster of the two at every N, including strong N = 4096
    (266 vs 279 ms). The tables use the pre-chosen implementation; both are in `scale_*.json`.

**Search ranges and boundaries** (`selection_*.json`):
- p ∈ {6, …, 12}; the model optimum is p = 9 in all 12 configurations, never a boundary.
- ξ ∈ [0.50, 1.30]: every p ≥ 7 has an interior ξ optimum. Only p = 6 at strong N = 4096 and uniform N = 2048 sits at
  ξ = 0.50; that order is predicted 2.3–2.5 × slower than the optimum.
- No M_cap hit: the FFT term alone at M_cap is 192 ms at N = 512 and 2.08 s at N = 4096.
- **Verification method:**
  - all confirmed candidates at N ≤ 1024: dense. 84 candidates verified in total, all ≤ τ, E_op 2.9e-9 … 7.9e-8;
  - optimum and runner-up at N ≥ 2048: ARPACK;
  - ARPACK and dense agree to 4 digits at N = 512 and 1024 (3.034e-8 / 3.633e-8 and 3.359e-8 / 3.032e-8).

## 6. Complexity: analytical work estimates vs finite-range empirical fits

Figures S1 (T_action vs N), S2 (T_action/(N log N) and T_action/N²), S3 (setup), S6 (parameters).

### 6.1 Analytical work counts (exact, from the selected parameters)

**Direct action (this implementation):**
- Exactly N(N − 1)/2 pair updates per action, independent of R_d (the image sum was folded into K^per in setup).
- O(N²) by construction: 8 128 … 8 386 560 pairs.

**Direct setup** (`direct_setup_evaluations` in the tables):
- Kept images ≈ 30 000 N, i.e. linear in N at fixed R_d, since images per particle are 29 462–31 661 at every N.
- Candidate evaluations = pairs × lattice shifts = 6.1e6 (N = 128) … 4.8e8 (N = 4096), a factor 78 for a factor 32 in N.
- The number of shifts falls from 751 to 57 as L grows towards R_d. Once L ≫ R_d it tends to a constant, and the
  evaluation count tends to O(N²).

**A different direct implementation could scale linearly.** A fixed-radius screened direct method that does not fold the
images into pair tensors (the image-resolved action, cell lists) does O(n_img) = O(30 000 N) work per action at fixed R_d
and density. This is linear in N.
- Its arithmetic count falls below the pair-summed N(N − 1)/2 only for N ≳ 6 × 10⁴. That is an analytic count, not
  measured here.
- So the O(N²) statement applies to the pair-summed implementation benchmarked here, not to every conceivable direct
  method.

**PPPM per action:**
- real space ∝ n_img = (135 … 346) N;
- spread + gather ∝ N p³ = 729 N;
- FFT + influence ∝ M³ log M³ with M³ ≈ 125 N.

At fixed parameters this is O(N log N). With certified parameters the real-space part grows by a factor 2.6 over
N = 128 … 4096 (§3.1).

**PPPM action:**

These are finite-range descriptions of N = 128 … 4096 on one machine, not asymptotic exponents.

## 8. Limitations and failures

- **Scope.** One machine, N ≤ 4096, two configuration families with one seed each. Nothing beyond N = 4096 was measured
  or extrapolated.
- **Timing variance:**
  - The Direct action at N = 4096 has a wide IQR ([1700, 2575] ms, n = 30); it is memory-bandwidth bound.
  - Large-N rounds are fewer: setup n = 5–6, action n = 30–50 at N ≥ 2048.
  - The conclusions (ratios ≥ 3 at N ≥ 2048) are far outside these ranges.
- **Certificates:**
  - Both certify truncation in exact arithmetic.
  - PPPM's quadrature term is an estimate (included in the budget, ~1e-13 relative).
  - Floating-point round-off of either operator is not certified. It is measured at ~1e-15 relative (method identity
    checks), eight orders below τ.
  - The PPPM mesh/Fourier certificate is N-coherent and increasingly conservative with N (§3.1). Its cost to PPPM grows
    with N: ξ falls and r_c grows.
- **Measured spectral norms at N ≥ 2048** are ARPACK estimates (lower bounds in exact arithmetic, tol 1e-6), not
  certificates. They agree with dense values to 4 digits wherever both were computed (N = 512, 1024; Direct also 2048).
- **Search restrictions** (p = 6…12, ξ ∈ [0.5, 1.3], M ≤ M_cap) are justified in §2 and checked for boundary hits (§3.1).
- **Implementations.** Both are pure NumPy, single-threaded (vectorised gathers and `bincount`), with no compiled
  kernels. Constants would change with compiled code; the crossover N could shift either way.
